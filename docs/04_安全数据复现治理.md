# CodeVerifier-Triage：安全、数据与复现治理

# 1. 安全原则

候选程序和测试输入均视为不可信。Docker 默认配置不是自动安全证明；SandboxFusion 也必须经过本项目自己的验收。

# 2. 推荐部署

- GPU 训练节点不直接运行候选代码；
- 独立 Linux 执行节点或 VM；
- 仅暴露内网 HTTP API；
- API 不接收任意 shell command，只接收结构化 language/code/tests/limits；
- 无网络出口；
- 非 root；
- 只读镜像 + tmpfs；
- cgroups v2；
- 每请求独立工作目录与进程组；
- 超时杀死后代；
- 输出截断；
- 限制并发和队列。

# 3. 状态语义

答案类：PASS、WRONG_ANSWER、COMPILE_ERROR、RUNTIME_ERROR、TIME_LIMIT、MEMORY_LIMIT、OUTPUT_LIMIT、INVALID_CODE。

基础设施类：SANDBOX_ERROR、INFRA_ERROR。

基础设施类不能自动映射成 reward 0。

# 4. 缓存

Cache key 必须包含 code、test suite hash、image digest、limit config。Infra error 不缓存；timeout 清洁环境重试一次。缓存命中仍记录原始运行 provenance。

# 5. 数据治理

- 原始测试和隐藏测试不进入 Git；
- prompt/RM/router 日志不含测试；
- 模型响应可能包含恶意或敏感文本，日志需限制与脱敏；
- 数据 revision、license、hash、来源必须记录；
- CodeScaler 根仓许可边界在发布前人工核验；
- 模型/数据权重只按各自许可证处理。

# 6. 复现

每个 run 必须有：git commit、working tree、contracts hash、upstream lock、模型/数据 revision、container digest、完整命令、resolved config、seed、机器清单、输入输出 artifact hash。

# 7. Retention

永久保留：合同、manifest、最终配置、原始指标、统计脚本、关键日志、final outputs、hash。

按策略清理：中间 checkpoint、缓存模型、重复执行 cache、临时容器层。清理前生成 manifest 和校验记录。

# 8. 事故响应

出现疑似容器逃逸、宿主不明进程、磁盘异常增长、凭据泄露或连续 OOM：停止执行服务，隔离节点，保存审计日志，轮换密钥，提交 failure report。未完成安全复审前不得恢复执行。
