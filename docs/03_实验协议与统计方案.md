# CodeVerifier-Triage：实验协议与统计方案

> 本文是所有离线和在线实验的统一 measurement contract。与本文冲突的临时脚本结果不得进入最终 Claim。

# 1. 实验单位

- Problem：最小统计与切分单位；
- Group：同一 problem、同一 policy checkpoint、同一 generation config 下的 n 个候选；
- Candidate：单个响应及其提取代码；
- Route Window：router 冻结和预算控制窗口；
- Training Run：一个独立训练 seed 的完整过程。

# 2. 候选、分数与标签

同一 group 内保持固定 n=4。RM top-1 ties 使用稳定 `candidate_id` 打破，不能依赖 DataFrame 行序。

标签：optimization FP、avoidable selection FP、mixed outcome。INFRA_ERROR group 不产生这三个标签，必须重试或剔除并报告。

# 3. 数据切分

所有切分按 problem hash。任何不同 checkpoint 的同题输出仍属于同一 split。risk calibration 与 dev 分开；RL final 独立且密封。

# 4. 离线指标

## 4.1 Risk classifier

- PR-AUC 为主；
- AUROC 辅助；
- recall@10/25/50% candidate-execution budget；
- precision@k；
- Brier、ECE；
- reliability diagram。

## 4.2 Selective prediction

Risk–coverage：按 risk 从低到高保留不执行样本，计算未验证区域的真实 error risk。

AURC/eAURC 必须注明实现公式和离散积分方式。

## 4.3 BoN

- CodeScaler-only top1；
- execute-all oracle；
- fixed-budget random/margin/UQ/router；
- BoN@4/8；
- selection regret；
- avoidable error recovery。

候选集固定，路由方法不得重新生成。

# 5. 在线指标

## 5.1 能力

- sample accuracy；
- task pass-any@4/8；
- 如报告 pass-all，单独命名；
- 每 benchmark 分项。

## 5.2 风险

- top-RM execution disagreement；
- dangerous FP；
- audited low-risk FP；
- router false negative；
- calibration by checkpoint/decile。

## 5.3 训练机制

- generated/effective groups；
- all-pass/all-fail；
- zero variance；
- resampling；
- KL；
- response/code length；
- invalid/compile/runtime/timeout；
- RM truncation；
- entropy/advantage distribution。

## 5.4 成本

分开报告：

- policy GPU-seconds；
- RM GPU-seconds；
- router CPU/GPU；
- execution CPU core-seconds；
- candidate executions；
- wall-clock；
- 每个通过样本成本。

不得任意合并为一个无可解释权重的“总成本分”。

# 6. Matched budget

P2、P4、P5、P6 必须匹配：问题、group size、生成候选数、token cap、optimizer step、adaptation、KL 和 checkpoint 频率。P4 与 P6 还匹配 candidate-execution budget。

若启用 upstream group filtering，必须匹配 total generated candidates 和 tokens，而不是只匹配 optimizer steps。

# 7. 统计

- Problem-level paired bootstrap，10000 次；
- 95% CI；
- 三独立训练 seed；
- 每 seed 单独报告；
- mean/std 与 problem bootstrap 解决不同层级不确定性；
- 不把同一 checkpoint 的多个 decoding seed当独立训练重复；
- 多预算/多指标以预注册主指标为准，其他标为探索性。

# 8. Checkpoint 与 final

checkpoint 选取只能依赖固定 final step 或 dev。Final 只运行一次。任何 final 后调整都产生新研究阶段，不能混入原 Claim。

# 9. Protocol deviation

以下均需 change request：prompt/template、extractor、test suite、RM input、token cap、group size、reward、KL、filtering、split、router feature、校准、主指标、checkpoint rule。
